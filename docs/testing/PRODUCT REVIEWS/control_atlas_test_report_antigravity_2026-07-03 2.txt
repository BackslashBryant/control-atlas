6. DEEP DIVE - TEMPLATE PRODUCTION
----------------------------------------------------------------
End-to-end testing of template production confirms it is severely broken:
1. Security Plan Starter: Slices controls array to one element. Only the first control in the baseline is output, and all subsequent controls are lost.
2. POA&M Starter, Continuous Monitoring Calendar, STIG Evidence Checklist, Reciprocity Checklist: These template downloads output a completely hardcoded single-row mock template that ignores the selected baseline and controls.
3. Inheritance Worksheet, Implementation Statement Worksheet, Evidence Expectation Matrix: These files successfully map dynamically over the controls list.
Files export successfully in all requested formats (Markdown, CSV, JSON, YAML) via the React download helper, but the contents of 5 out of 8 template types are incorrect, stubbed, or truncated.

----------------------------------------------------------------
7. DEEP DIVE - INHERITANCE
----------------------------------------------------------------
Testing of control inheritance features reveals data correctness is maintained, but navigation UX is broken:
1. Inheritance relationships (requires/inherits links) are present and directionally correct in the underlying edges.json dataset.
2. Tracing works in the Threat-to-controls workbench, resolving ATT&CK techniques through D3FEND countermeasures to NIST controls.
3. However, clicking playbook inheritance buttons (e.g. Playbooks -> "Control Inheritance Model" -> "Open related map") changes the URL hash to "#/atlas-map?node=PL-2" but fails to update the UI due to the client-side routing defect (CA-001).
4. No data inconsistencies were found in the inheritance links, but the user cannot navigate inheritance paths without manual refreshes.

----------------------------------------------------------------
8. CROSS-CUTTING THEMES
----------------------------------------------------------------
1. Client-Side Routing Failure: Every single inline transition in the application updates the URL hash but fails to trigger a React render. This impacts explore search results, playbook buttons, footer links, and comparison workbench actions. The application is unusable without continuous manual browser reloads.
2. Static/Empty Data Coverage: The database is filled with 25.4% disconnected orphans, and DISA STIG/SRG namespaces are complete skeletons with exactly 1 record each.
3. Lack of Responsive Design: No media queries exist in the app-wide CSS, causing the navigation header to wrap and overlap on mobile/tablet viewports, breaking mobile suitability.

----------------------------------------------------------------
9. WHAT I COULD NOT TEST
----------------------------------------------------------------
1. STIG/SRG to NIST controls workbench: Cannot be functionally validated because the database lacks actual STIG and SRG data.
2. Large-scale graph visualization responsiveness on mobile: The graph rendering component requires a large screen, and due to the routing bug and layout clipping, it could not be fully operated on mobile viewports.
